3. 必须覆盖早期报告的毛坯结论

E\summary.txt、results.json 中早期“毛坯修改成功”仅证实旧组结构字段持久化，不能作为实际组件毛坯修改成功证据。本报告的后续组件核查优先。

原件独立副本的 MachineDefApi 读回：唯一 stock cylinder，radius21.5、innerRadius19、length100，故外径43/内径38/长度100 mm；base[0,0,0]，axis[-1,0,0]。旧组 pg3.stock_def 及 policy 则为150/0/150。不能把两个表示混用，也不能仅凭本轮回读自动重签可信模板/policy。实际仿真消费尚未运行验证。

旧结构接口 GroupsMachineGroup(nullptr)、Cnc::OpMgr::OpGroupsAPI::UpdateGroup(const op_group&)：分别 OD150→145、长度150→140、预孔0→10并开孔，可保存重开；但实际毛坯组件与边界89不变。失败原因是修改了另一套记录，未改到目标组件。

官方组件读写候选：StorageControllerFactory().CreateDatabaseStorageController()，Initialize(machine_ent_idn,false)，Read()；IStockComponent.GetGeometry/SetGeometry，ICylinderParametricGeometry.SetRadius/SetLength/SetInnerRadius，IStorageController.Write(IMachineContext&) 与 Write(IMachine&)。
独立测试 OD43→45、长度100→98、内径38→36及38→0：SetGeometry成功；实际提交 Write 返回 success=false、ResultCode=1（官方枚举 Unimplemented）、文本“Unimplemented.”。另一个 Write 重载亦相同。保存成功但重开仍43/38/100。
结论：本机这两条官方存储写入路径不可用；其他接口或 UI 路径尚未验证，不能扩大为“Mastercam 没有毛坯修改能力”。UI 回退曾遇 Windows 锁屏，用户后来已解锁；因用户决定收口而未继续 UI 测试。
证据：E\closure\component-{od,length,bore,solid}\、component-od-v2\ 的 before/after/reopened-machine.txt、write.txt、result.txt、test.mcam；E\closure\*-boundary.json；E\machine-write*.cpp 和 build-machine-write*.ps1。
边界89原始坐标尚未完成缩放单位确认，不把原始整数坐标直接称作 mm。

4. 零点、平面、偏置：已有原生能力，完整链路未接入

原生操作 GET/REWRITE 单写 WCS.origin，Save() 与 SaveAs() 对照均不能保住该 origin；同次修改的进给能保存，排除了“根本没保存”。不要重复把该失败归因于未点保存。
成功路径：new MCView；复制基准平面矩阵；设置 ViewOrigin/ViewName；Commit() 建立可编辑命名平面；通过原生接口同步机床组 pg1.stock_view 的平面ID/世界原点及全部七工序 WCS 平面ID/原点；SaveAs→New→Open→回读。
独立 X/Y/Z 测试分别将世界原点0改为2 mm，均持久化。只改一个工序的命名平面也能保存，但重开出现车床 WCS/毛坯平面不一致警告，不能作为可用的一致设置。
工序 WCS.woff_n -1→2 也已保存重开；它是工程偏置选择，本轮没有验证输出G代码映射，更没有修改控制器偏置数值。
世界坐标、WCS、构图平面和刀具平面必须分开。平面52（车床左上刀塔）下，world X→view Z、world Y→view X、world Z→view Y；转换无二倍因子，不把世界原点X直接当车床直径X。
低层写入后 dirty 可保持false，不能以此证明旧刀路有效。未验证任意旋转/所有机床组配置。
证据：E\origin-persistence-conclusion.txt、origin-save-check\、origin-official-plane\、origin-official-group\；E\closure\origin-y\、origin-z\、axis-transform.txt。

5. 装夹：有候选接口，但当前工程目标组件缺失

旧组 gripLength25→24 可持久化，夹具几何/实际夹持未由此改变。真实组件树两侧 chuck 的 jawsCount=3，但 GetChuckJaws()==null，夹爪组件总数0；“三爪数量”不能冒充已有夹爪模型。
IChuckJawsComponent.Get/SetGripLength、Get/SetStockStickOut 是安装SDK候选；类型/筒夹也有组件API，但未实现完整映射或测试配置替换。
原生夹持探针因没有唯一夹爪组件，防护返回14而没有尝试写入。这是目标配置缺失，不是证明 setter 不支持。夹具类型、夹持长度、伸出量分别的真实持久化与仿真消费均未完成。
现有插件 setup_snapshot 只取旧 gripLength；模板关于装夹/伸出量的要求未完全核验。setup_unconfirmed 仍需要基准资料和用户实物确认，不能仅换成SDK回读就解除。
证据：E\closure\component-grip\、component-od\before-machine.txt、grip-boundary.json。

6. 精加工参数与表面质量：原生写入已有证据，不能承诺Ra

原生 operation_manager GET/REWRITE：op3外圆精车feed -0.30→-0.25（每转模式负号约定）、速度295→290（use_css=true，不能称作RPM）、stock_x0→0.03、stock_z0→0.04；均保存重开。op5内孔精车feed -0.10→-0.09也通过。CSS true→false模式切换持久化；不能保持同一数值就认定加工意义相同。
X余量径向/直径约定及CSS具体单位到产品字段的完整映射尚未收口，不准直接套用界面“rpm”标签。

刀具半径：tl.crad 与 tl.ltool.radius 单独写入可保存，但二者互不自动同步。实际刀具对象必须 Clone，取 MainInsert，SetCornerRadius(0.45,true)，再将 insert 赋回 tool.MainInsert，IToolSystem.Update(tool)。未赋回的早期测试 Update虽true，实际半径仍0.4，不能称成功。
正确写回后刀具半径0.4→0.45 mm保存重开。Update 配置 Automate/UpdateAllOperations 并确认本机警告后，slot1对应op1/2/3的两个操作半径同步0.45，七工序dirty=true。Automate仍弹窗，尚未达到无人值守接入要求；超时期间没有重发原命令。

原生 surf_fin_feed=true、feed=1.6 的理论表面质量进给模式可保存重开；官方帮助描述单位microns，并转换每转进给影响刀路，非纯备注。但该理论表面质量量不等于现场Ra，本轮未再生验证派生进给/刀路，不设计Ra→参数映射。
source_verified=false、process_response=unverified、achieved=false继续保留；finish_requirement_conflict 属于要求来源冲突，SDK能力不会自动解除。
证据：E\finish-*-reopened.json；E\closure\finish5-feed\、css-mode\、corner-cache\、insert-cache\、tool-object*\、theoretical-finish\；本地帮助 Toolpaths\Turning\Toolpath_Parameters_Lathe.htm。
