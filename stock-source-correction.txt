2. 读到的对象
ReadMachine先取 GroupsMachineGroup(nullptr)，用其 ogi.pg1.machine_ent_idn、allowFallback=false 初始化 DatabaseStorageController，Read后递归遍历 GetMachine().GetRoot()。
读到路径为 Default -> Left Spindle Group -> Lathe Left Spindle C Axis -> Lathe Chuck -> stock，type33，能转换IStockComponent与ICylinderParametricGeometry。
该对象radius21.5、innerRadius19、length100、base[0,0,0]、axis[-1,0,0]，据此组件几何换算外径43/内径38/长度100 mm。
探针没有记录machine_ent_idn实际数值、组件唯一标识、选中/启用状态、关联操作或仿真初始毛坯选择；遍历类型匹配不构成“当前消费者采用该毛坯”的证据。

3. 矛盾与未解决项
同一测试的旧组stock_def读回150/0/150、holeInStock=false，边界引用[89,0]，display=true。边界89有4条线，原始径向坐标19000..21500；其缩放单位和当前有效性没有核实。
因此同一七工序文件中确有互相矛盾的毛坯相关记录。组件树/边界可能是旧配置残留，可能属于不同消费者，或探针选择了不适用的对象；现有证据不能区分这些解释。
未实测当前加工/仿真读取哪个记录；未核对stock组件孔启用标志（几何innerRadius本身不证明孔已启用）；也没有证实组件与边界89的唯一绑定关系。
用户确认无孔，不能因组件innerRadius19便改判成有孔。旧组holeInStock=false也不足以证明其150/0/150是当前有效规格。
结论：有效毛坯配置仍未解决；43/38/100不作为新基准，不自动改写policy、批准模板或现场输入。

4. 既有能力结论的准确范围
旧组字段可持久化，但未证明修改了当前有效毛坯。
MachineDefApi的两种Write对本次读取的机床定义上下文返回Unimplemented；失败事实成立，但不证明该上下文就是当前有效毛坯的正确写入目标，也不证明Mastercam整体不支持毛坯修改。
零点、进给、工具等独立测试不因本修订被宣称无效；它们同样不能证明毛坯有效配置。
